# Automation map

This map is the maintainer-facing index of the repository's GitHub Actions.
Every workflow has an explicit display-group prefix (except the signed-identity
attester) and a run name that identifies its event/source. Routing and major
release/deployment boundaries publish job summaries explaining selection or outcome. PR routing
is deliberately fail-closed: an unknown path, policy/control change, or missing
trusted-base planner selects the complete affected suite.

## Required-check compatibility

GitHub branch protection currently names historical job contexts, not workflow
files. The `plan` and `dependency-review` jobs are tiny, always-reporting bridges
which fail unless their clearly named replacement jobs succeeded. They keep the
live ruleset stable while contributors learn the clearer group names. The
regression test in `scripts/ci-required-contexts.test.mjs` prevents an accidental
missing or path-filtered required context.

## Routing and safe operation

The machine-readable selectors are in
`contracts/ci-change-plan-policy.json`; the trusted planner is
`scripts/ci-change-plan.mjs`. Pull-request planners run from the base revision,
not PR code. Workflows never use top-level PR `paths` filters for required
contexts, because that would leave a required check pending. A selection summary
in every relevant run records which expensive lane executed or safely no-opped.
