## P1-09 security hardening

An authenticated provider audit found and corrected safe, reversible settings on
both repositories: private vulnerability reporting, Dependabot alerts and security
updates, secret scanning, push protection, non-provider patterns, validity checks,
read-only default workflow tokens, disabled workflow PR approvals, and required
full-SHA action pinning are enabled.

Starter now adds CodeQL for Java and JavaScript/TypeScript plus moderate-severity
dependency review. Template now adds the same pinned full-history Gitleaks control
as Starter and removes an unnecessary pull-request write permission. Starter release
evidence now generates a populated JVM CycloneDX SBOM alongside its npm SBOM. The
[dated recovery tabletop](../../security/recovery-exercise-2026-08-27.md) records
the tested response sequence and remaining provider/human limitations.

P1-09 remains partial: no branch ruleset protects `main`, provider allowed-actions
is still broad, Maven/Pages environment controls need tightening, SBOMs are not
signed attestations bound to published bytes, and backup-owner recovery has not been
exercised.

- Starter workflow policy passed with 11 workflows, 12 pinned actions, and four
