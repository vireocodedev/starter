# Consumption and release semantics

The BOM is an alignment boundary, not an aggregate starter.

## Why it exists

Dependency platforms are easy to misuse as hidden bundles or absolute locks. Vireo keeps the boundary narrow so consumers can predict exactly what an import changes, override dependencies deliberately, and upgrade the JVM library family as one reviewed unit.

## What is aligned

| Coordinate | Role |
| --- | --- |
| `com.vireocode:vireo-starter-core` | Shared foundations |
| `com.vireocode:vireo-starter-auth` | Authentication defaults |
| `com.vireocode:vireo-starter-queryengine` | Query Engine capability |
| `com.vireocode:vireo-starter-history` | History capability |
| `com.vireocode:vireo-starter-offline` | Offline capability |
| `org.springframework.boot:spring-boot-dependencies` | Compatible third-party dependency line |

All Vireo modules resolve to the BOM's version. Importing it does not add those modules, apply Spring Boot's Gradle plugin, or publish a transitive application architecture.

## Gradle policy

Use `platform(...)` by default. Its constraints participate in normal conflict resolution, allowing an application to make an explicit stronger choice when necessary. `enforcedPlatform(...)` is appropriate only when the application deliberately wants hard enforcement; published libraries should not force that decision onto downstream consumers.

An application-owned third-party override is valid, but compatibility ownership moves to that application and its complete verification suite.

## Release proof

All Vireo JVM artifacts intentionally share one version in `jvm/gradle.properties`. A JVM release publishes the five libraries and the BOM together.

The local `bomContractCheck` task validates the Gradle platform declarations and parses the generated Maven POM. It fails on missing, extra, or mismatched Vireo constraints; an unexpected Spring Boot import; incorrect BOM coordinates; or non-BOM packaging. The release workflow then resolves the published platform and every versionless module from GitHub Packages using a cold Gradle cache.
