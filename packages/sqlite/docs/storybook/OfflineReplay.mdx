# Offline replay

`replayOfflineSyncBatch` applies one ordered batch and classifies every result as successful, permanently failed, or retryable. Cleanup occurs before successful commands are deleted; status refresh happens after every non-empty batch.

The application supplies the network call and domain cleanup. SQLite queue clients supply the remaining dependencies without coupling replay to an HTTP library.

## Domain command contract

Offline replay stays opt-in at the application boundary. This order-quantity example captures a UUID-addressed domain command and replays it with the same command identifier expected by the paired JVM handler. Applications still own admission, durable storage, idempotency, and conflict recovery.
