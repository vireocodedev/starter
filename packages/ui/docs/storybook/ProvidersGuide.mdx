## Provider Nesting Order

Providers should be nested in this recommended order (outermost → innermost):

```tsx
import {
  RgoThemeProvider,
  RgoQueryClientProvider,
  RgoLocalizationProvider,
  VireoIconRegistryProvider,
  VireoConfirmationProvider,
  AppSnackbarProvider,
} from "@vireocodedev/starter-ui";

function App() {
  return (
    <RgoThemeProvider theme={theme}>
      <RgoQueryClientProvider client={queryClient}>
        <RgoLocalizationProvider>
          <VireoIconRegistryProvider icons={icons}>
            <VireoConfirmationProvider>
              <AppSnackbarProvider>
                <YourApp />
              </AppSnackbarProvider>
            </VireoConfirmationProvider>
          </VireoIconRegistryProvider>
        </RgoLocalizationProvider>
      </RgoQueryClientProvider>
    </RgoThemeProvider>
  );
}
```

## RgoThemeProvider

**Required** — wraps the app in MUI `ThemeProvider` and applies `CssBaseline`.

```tsx
import { createTheme } from "@mui/material/styles";
import { RgoThemeProvider } from "@vireocodedev/starter-ui";

const theme = createTheme({
  palette: {
    primary: { main: "#1976d2" },
  },
});

<RgoThemeProvider theme={theme}>
  <App />
</RgoThemeProvider>;
```

## RgoLocalizationProvider

Sets up MUI date/time localization with the `dayjs` adapter and waits for i18next to be ready before rendering children. Country display names are resolved independently through `getCountryName` from `@vireocodedev/starter-ui/country`.

```tsx
import { RgoLocalizationProvider } from "@vireocodedev/starter-ui";

<RgoLocalizationProvider>
  <App />
</RgoLocalizationProvider>;
```

No props required. Uses the i18n instance configured elsewhere.

## VireoConfirmationProvider

Provides promise-based confirmation decisions via the `useVireoConfirmation` hook.

```tsx
import { VireoConfirmationProvider, useVireoConfirmation } from "@vireocodedev/starter-ui";

// In your provider tree
<VireoConfirmationProvider>
  <App />
</VireoConfirmationProvider>;

// In any component
function DeleteButton() {
  const confirm = useVireoConfirmation();

  const handleDelete = async () => {
    const confirmed = await confirm({
      title: "Delete Item",
      message: "This action cannot be undone.",
      confirmLabel: "Delete",
      cancelLabel: "Cancel",
      confirmColor: "error",
    });

    if (confirmed) {
      // proceed with deletion
    }
  };

  return <button onClick={handleDelete}>Delete</button>;
}
```

## AppSnackbarProvider

Mounts sonner's `Toaster` with responsive placement (top-right on mobile,
bottom-center on desktop) and follows the active MUI theme mode.

```tsx
import { AppSnackbarProvider, toast } from "@vireocodedev/starter-ui";

<AppSnackbarProvider>
  <App />
</AppSnackbarProvider>;

// Anywhere in the tree:
toast.success("Saved");
```

The provider takes no props — placement, duration and theme are derived from
the viewport and theme. Import `toast` from `@vireocodedev/starter-ui` rather
than from `sonner` directly so the library owns the toast implementation.

## VireoIconRegistryProvider

Provides a type-safe icon registry. Icons are registered by the consumer app through TypeScript interface augmentation.

### Step 1: Augment the Registry

```tsx
// In your app's type declarations (e.g., icons.d.ts)
import type { SvgIconComponent } from "@mui/icons-material";

declare module "@vireocodedev/starter-ui" {
  interface VireoIconRegistry {
    home: SvgIconComponent;
    settings: SvgIconComponent;
    delete: SvgIconComponent;
  }
}
```

### Step 2: Provide the Icons

```tsx
import { VireoIconRegistryProvider } from "@vireocodedev/starter-ui";
import HomeIcon from "@mui/icons-material/Home";
import SettingsIcon from "@mui/icons-material/Settings";
import DeleteIcon from "@mui/icons-material/Delete";

const icons = { home: HomeIcon, settings: SettingsIcon, delete: DeleteIcon };

<VireoIconRegistryProvider icons={icons}>
  <App />
</VireoIconRegistryProvider>;
```

### Step 3: Use Icons

```tsx
import { useVireoIcons, VireoIcon } from "@vireocodedev/starter-ui";

// Via hook
function MyComponent() {
  const { muiIconsMap } = useVireoIcons();
  const HomeIcon = muiIconsMap.home;
  return <HomeIcon />;
}

// Via component
<VireoIcon name="home" fontSize="large" color="primary" />;
```

## useRgoSseEmitter

Manages Server-Sent Events (SSE) connections with typed event handlers. This is a hook rather than a provider — mount it
once in a component near the root of the tree that needs the connection.

```tsx
import { useRgoSseEmitter } from "@vireocodedev/starter-ui";

function AppEvents() {
  useRgoSseEmitter({
    url: "/api/events",
    eventHandlers: {
      notification: data => handleNotification(data),
      update: data => handleUpdate(data),
    },
    withCredentials: true,
  });

  return null;
}
```

## RgoProviders Utility

A utility component that reduces provider nesting boilerplate by composing multiple providers:

```tsx
import {
  RgoProviders,
  RgoThemeProvider,
  VireoConfirmationProvider,
  AppSnackbarProvider,
} from "@vireocodedev/starter-ui";

const providers = [
  props => <RgoThemeProvider theme={theme} {...props} />,
  props => <VireoConfirmationProvider {...props} />,
  props => <AppSnackbarProvider {...props} />,
];

<RgoProviders list={providers}>
  <App />
</RgoProviders>;
```

This is equivalent to manually nesting the providers but keeps the code flat and composable.
