# RgoOfflineCacheService

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

An IndexedDB-backed offline cache service using the `idb` library. Supports versioned schema upgrades, bulk data loading with batched writes, and selective cache reloading.

---

## Why it exists

Client-side offline caching with IndexedDB is powerful but low-level. `RgoOfflineCacheService` wraps the `idb` library to provide a streamlined API for opening/upgrading databases, bulk-loading data in configurable batches, and clearing stores — all with full TypeScript inference over the `DBSchema` type.

---

## Setup

```tsx
import { RgoOfflineCacheService } from "@vireocodedev/starter-ui";
import type { DBSchema } from "idb";

// Define your IndexedDB schema
interface MyDBSchema extends DBSchema {
  users: {
    key: number;
    value: { id: number; name: string; email: string };
  };
  products: {
    key: string;
    value: { sku: string; name: string; price: number };
    indexes: { "by-name": string };
  };
}

// Define stores with key paths and indexes
const stores = {
  users: {
    options: { keyPath: "id" },
    indexes: {},
  },
  products: {
    options: { keyPath: "sku" },
    indexes: {
      "by-name": { keyPath: "name", options: { unique: false } },
    },
  },
};

// Create the service
const offlineCache = new RgoOfflineCacheService<MyDBSchema>(stores, {
  version: 1,
  debug: false,
});

// Initialize (opens/upgrades the database)
await offlineCache.init();
```

---

## Usage

```tsx
// Load data into the cache (clears existing data first)
await offlineCache.loadCache({
  users: [
    { id: 1, name: "Alice", email: "alice@example.com" },
    { id: 2, name: "Bob", email: "bob@example.com" },
  ],
  products: [{ sku: "A001", name: "Widget", price: 9.99 }],
});

// Access the IDB database directly for reads
const db = offlineCache.db;
const user = await db.get("users", 1);
const allProducts = await db.getAll("products");
```

## Behavior

- **Initialization** — `init()` opens the database with the configured version. If the version is higher than the existing one, the `upgrade` callback creates any missing object stores and their indexes.
- **Blocking / Blocked** — if other tabs hold an older connection, console warnings are logged (`blocked` / `blocking` events).
- **Cache loading** — `loadCache` first clears all stores (except those in `skipCacheReloadFor`), then bulk-inserts items using `readwrite` transactions in batches of 1 000 records per transaction.
- **Error handling** — initialization and bulk-save errors are logged and re-thrown. Cache-load errors are logged but do not throw.
- **Console logging** — all operations emit styled `console.debug` / `console.warn` / `console.error` messages tagged with `RgoOfflineCacheService` and the store name.
