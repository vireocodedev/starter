# RgoWebWorkerService

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

A typed web worker communication service with event-based messaging. Provides `on` / `emit` semantics over `postMessage`, with lifecycle hooks for intercepting messages.

---

## Why it exists

Raw `Worker.postMessage` is untyped and requires manual event dispatching. `RgoWebWorkerService` adds a fully typed event layer on top — incoming messages from the worker are dispatched to registered handlers via `on`, and outgoing messages are sent via `emit` with compile-time payload enforcement. Lifecycle hooks (`onBeforeMessage`, `onAfterMessage`) allow cross-cutting concerns like logging or state synchronization.

---

## Setup

```tsx
import { RgoWebWorkerService } from "@vireocodedev/starter-ui";

// Define the worker→main event schema (handled by RgoEventSchema)
// and the main→worker event schema

const workerService = new RgoWebWorkerService<{
  process: { input: number[] };
  cancel: undefined;
}>({
  url: new URL("./my-worker.ts", import.meta.url),
  onInit() {
    console.log("Worker initialized");
  },
});

// Create the worker and start listening
workerService.init();
```

---

## Usage

```tsx
// Listen for messages from the worker (typed via RgoEventSchema)
workerService.on("result", data => {
  console.log("Received result:", data);
});

workerService.on("progress", data => {
  console.log(`Progress: ${data.percent}%`);
});

// Send messages to the worker (typed via TWorkerSchema)
workerService.emit("process", { input: [1, 2, 3, 4, 5] });

// Events with no payload can be emitted without a second argument
workerService.emit("cancel");
```

## Message protocol

Messages are exchanged as plain objects with `type` and `data` fields:

```ts
// Main → Worker
worker.postMessage({ type: "process", data: { input: [1, 2, 3] } });

// Worker → Main
self.postMessage({ type: "result", data: { output: [2, 4, 6] } });
```

---

## Worker-side example

```ts
// my-worker.ts
self.onmessage = (e: MessageEvent) => {
  const { type, data } = e.data;

  if (type === "process") {
    const result = data.input.map((n: number) => n * 2);
    self.postMessage({ type: "progress", data: { percent: 50 } });
    self.postMessage({ type: "result", data: { output: result } });
  }
};
```

---

## Behavior

- **Multiple handlers** — `on` accumulates handlers per event type. All registered handlers run in parallel via `Promise.all` when a message arrives.
- **Lifecycle hooks** — `onBeforeMessage` and `onAfterMessage` wrap each individual handler invocation, not the batch. They receive `this` bound to the service instance.
- **Unknown events** — if a message arrives with a `type` that has no registered handler, a `console.warn` is logged.
- **Error handling** — if any handler throws, the error is caught and logged via `console.error`. Other handlers for the same event still execute.
- **Worker type** — the worker is created with `type: "module"`, enabling ES module imports inside the worker script.
