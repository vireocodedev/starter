# RgoLocalStorageService

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

A type-safe wrapper around `localStorage` backed by Zod schemas. Values are validated on read, automatically falling back to defaults when the stored data is missing or fails validation.

---

## Why it exists

Raw `localStorage` returns untyped strings and silently accepts any value. `RgoLocalStorageService` solves this by coupling a Zod schema to the storage layer — every `get` call parses and validates the stored JSON, and every `set` call serializes type-checked values. If a stored value is corrupt or doesn't match the schema, the service transparently resets it to the configured default.

---

## Setup

```tsx
import { z } from "zod";
import { RgoLocalStorageService } from "@vireocodedev/starter-ui";

const appSettingsSchema = z.object({
  theme: z.enum(["light", "dark"]),
  language: z.string(),
  sidebarCollapsed: z.boolean(),
  recentItems: z.array(z.string()),
});

const settingsStorage = new RgoLocalStorageService(appSettingsSchema, {
  theme: "light",
  language: "en",
  sidebarCollapsed: false,
  recentItems: [],
});
```

---

## Usage

```tsx
// Get a value — validated against the Zod schema
const theme = settingsStorage.get("theme"); // "light" | "dark"

// Set a value — type-safe, serialized as JSON
settingsStorage.set("theme", "dark");

// Arrays work as expected
const items = settingsStorage.get("recentItems"); // string[]
settingsStorage.set("recentItems", [...items, "new-item"]);
```

## Behavior

- **First access** — if the key does not exist in `localStorage`, the default value is written and returned.
- **Validation failure** — if the stored JSON does not satisfy the Zod schema for that key, the default is restored automatically.
- **Parse failure** — if `JSON.parse` throws (corrupted data), the default is restored automatically.
- **Serialization** — all values are stored as `JSON.stringify`-ed strings.
- **Type inference** — keys and value types are fully inferred from the Zod schema.
