# RgoLocalizationProvider

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

Orchestrates date/time localization for MUI X Date Pickers (via `dayjs`) and registers country name translations (via `i18n-iso-countries`). Blocks rendering until `i18next` is ready, ensuring downstream components always have access to locale data.

---

## Why it exists

Internationalized applications need three i18n layers working together:

1. **Text translations** — handled by `react-i18next` (configured separately).
2. **Date/time formatting** — MUI X Date Pickers need a locale-aware `dayjs` adapter.
3. **Country names** — forms with country pickers need localized country name resolution.

`RgoLocalizationProvider` wires up layers 2 and 3 and synchronizes them with the current `i18next` language. It also acts as a rendering gate — children don't mount until translations are loaded.

---

## Provider setup

```tsx
import { RgoLocalizationProvider } from "@vireocodedev/starter-ui";

// i18next must be initialized BEFORE this provider mounts.
// Typically done in a parent RgoInitializable or an app-level init.

function App() {
  return (
    <RgoLocalizationProvider>
      <YourApplication />
    </RgoLocalizationProvider>
  );
}
```

    {children}
  </LocalizationProvider>

## Rendering gate behavior

The provider calls `useTranslation()` from `react-i18next` and checks the `ready` flag. Until `i18next` finishes loading translation resources (which may be async — e.g., fetched from a backend), the provider renders an empty fragment.

This means:

- No layout shift from untranslated content.
- No "flash of English" while resources load.
- Date pickers won't mount until the correct locale adapter is resolved.

## Country name registration

On first mount, `RgoInitializable` runs the `onInit` function once, which registers country locale data:

```tsx
import countries from "i18n-iso-countries";

// After registration, you can use:
countries.getName("HR", "en"); // → "Croatia"
countries.getName("HR", "hr"); // → "Hrvatska"
countries.getName("HR", "de"); // → "Kroatien"
```

This is used by any component that needs to display country names in the user's language (e.g., country select dropdowns, address forms).

## Consumer hooks

### `useTranslation()` (from `react-i18next`)

Use `useTranslation` directly from `react-i18next`. Pass the namespace that matches your translation resources:

```tsx
import { useTranslation } from "react-i18next";

function Greeting() {
  const { t } = useTranslation("translation");

  return <h1>{t("welcome.title")}</h1>;
}
```

**Signature:**

```ts
import { useTranslation } from "react-i18next";

const { t, i18n, ready } = useTranslation("translation");
// or for the rgo-ui namespace:
const { t } = useTranslation("rgo-ui");
```

Returns the standard `react-i18next` response: `{ t, i18n, ready }`.

### Date pickers

MUI X Date Pickers automatically pick up the locale from `LocalizationProvider`:

```tsx
import { DatePicker } from "@mui/x-date-pickers/DatePicker";

function BirthdayField() {
  return <DatePicker label="Date of birth" />;
  // Automatically uses hr/en/de/... formatting based on current i18n language
}
```

---

## Nesting order

Must be placed **after** `RgoThemeProvider` (date pickers need MUI theme) and **before** components that use date pickers or translated text:

```
RgoThemeProvider
  └─ RgoLocalizationProvider    ← here
       └─ RgoConfirmProvider    (uses translated button labels)
            └─ ...
```

## Real-world consumer app pattern

Consumer apps typically wrap `RgoLocalizationProvider` in their own initializable provider that configures `i18next`:

```tsx
import { RgoLocalizationProvider, RgoInitializable, type RgoProvider } from "@vireocodedev/starter-ui";
import { configureI18nClient } from "@vireocodedev/starter-ui";
import i18n from "i18next";
import { AppTranslations } from "./translations";

function onInit() {
  configureI18nClient(i18n, { resources: AppTranslations });
}

export const AppLocalizationProvider: RgoProvider = ({ children }) => (
  <RgoInitializable onInit={onInit}>
    <RgoLocalizationProvider>{children}</RgoLocalizationProvider>
  </RgoInitializable>
);
```

---

## Key details

- **No custom context** — delegates to MUI X's `LocalizationProvider` and `react-i18next`.
- **Blocks rendering** until i18next is ready — acts as a Suspense-like gate.
- **Country locale registration is idempotent** — `RgoInitializable` ensures `onInit` runs exactly once.
- **dayjs locale imports are bundled** — all 8 locale files are statically imported (no dynamic loading).
- **i18next must be initialized externally** — this provider does not configure i18next itself; it only consumes it.
