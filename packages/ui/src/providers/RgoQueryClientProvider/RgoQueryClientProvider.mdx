# RgoQueryClientProvider

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

Thin wrapper around TanStack Query's `QueryClientProvider`. Injects a `QueryClient` instance into the React tree so that `useQuery`, `useSuspenseQuery`, `useMutation`, and all other TanStack Query hooks can function.

---

## Why it exists

TanStack Query requires a `QueryClient` instance delivered via context. This legacy wrapper remains temporarily available until the integrations phase; new applications can use TanStack's provider directly inside `VireoProviderComposer`.

---

## Provider setup

```tsx
import { QueryClient } from "@tanstack/react-query";
import { RgoQueryClientProvider } from "@vireocodedev/starter-ui";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000, // 5 minutes
      retry: 1,
      refetchOnWindowFocus: false,
    },
  },
});

function App() {
  return (
    <RgoQueryClientProvider client={queryClient}>
      <YourApplication />
    </RgoQueryClientProvider>
  );
}
```

## What it renders

```tsx
<TanstackQueryClientProvider client={client}>{children}</TanstackQueryClientProvider>
```

A direct delegation — no extra logic, no additional context layers.

## Consumer hooks

There is no custom consumer hook. Use TanStack Query's standard hooks:

### Queries

```tsx
import { useQuery, useSuspenseQuery } from "@tanstack/react-query";

function UserList() {
  const { data, isLoading, error } = useQuery({
    queryKey: ["users"],
    queryFn: () => fetchUsers(),
  });

  if (isLoading) return <Skeleton />;
  if (error) return <ErrorMessage error={error} />;

  return <List items={data} />;
}
```

### Mutations

```tsx
import { useMutation, useQueryClient } from "@tanstack/react-query";

function CreateUserButton() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (newUser: CreateUserDto) => api.createUser(newUser),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
  });

  return (
    <button onClick={() => mutation.mutate({ name: "Jane" })} disabled={mutation.isPending}>
      {mutation.isPending ? "Creating..." : "Create User"}
    </button>
  );
}
```

### Cache access

```tsx
import { useQueryClient } from "@tanstack/react-query";

function CacheInspector() {
  const queryClient = useQueryClient();

  const clearCache = () => queryClient.clear();
  const invalidateUsers = () => queryClient.invalidateQueries({ queryKey: ["users"] });

  return (
    <>
      <button onClick={clearCache}>Clear all cache</button>
      <button onClick={invalidateUsers}>Refresh users</button>
    </>
  );
}
```

## Nesting order

`RgoQueryClientProvider` should be placed **after** `ThemeProvider` and **before** any feature providers that perform data fetching:

```
ThemeProvider
  └─ RgoQueryClientProvider    ← here
       └─ RgoLocalizationProvider
            └─ ...feature providers that call useQuery
```

## Real-world consumer app pattern

```tsx
import { RgoQueryClientProvider } from "@vireocodedev/starter-ui";
import { QueryClient } from "@tanstack/react-query";

const QUERY_CLIENT = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5,
      retry: false,
    },
  },
});

export function AppQueryClientProvider({ children }: React.PropsWithChildren) {
  return <RgoQueryClientProvider client={QUERY_CLIENT}>{children}</RgoQueryClientProvider>;
}
```

## Key details

- **No custom context** — delegates entirely to TanStack Query's internal context.
- **Single instance** — create the `QueryClient` **outside** of React (module scope) to avoid re-creating it on every render.
- **Configuration is on the client, not the provider** — all default options, retry logic, and cache behavior live on the `QueryClient` instance itself.
- **Companion hook `useVireoMutation`** — adds optional Vireo notifications and Zod-validated error details while preserving TanStack mutation options.
