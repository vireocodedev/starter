# RgoInitializeProvider

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

Guards its children behind an async initialization routine. Runs the provided `onInit` callback once on mount, renders nothing until it resolves, and propagates errors by re-throwing them (to be caught by an error boundary). This is a **side-effect-only provider** — it does not create a React context.

---

## Why it exists

Many apps need to perform async setup before rendering — fetching configuration, authenticating, hydrating caches, etc. Without a dedicated component this logic ends up scattered across top-level `useEffect` calls with manual `ready` / `error` state.

`RgoInitializeProvider` encapsulates the full lifecycle:

1. Calls `onInit` on mount.
2. Renders nothing (`null`) until the promise resolves.
3. Supports an optional cleanup function returned from `onInit`, invoked on unmount.
4. Throws the error if `onInit` rejects, letting an error boundary handle it.

---

## Provider setup

```tsx
import { RgoInitializeProvider } from "@vireocodedev/starter-ui";

function App() {
  return (
    <RgoInitializeProvider
      onInit={async () => {
        await loadAppConfig();
        await authenticateUser();
      }}
    >
      <YourApplication />
    </RgoInitializeProvider>
  );
}
```

---

## Returning a cleanup function

`onInit` can optionally return a cleanup function (sync or async). It will be called when the provider unmounts, similar to a `useEffect` cleanup.

```tsx
<RgoInitializeProvider
  onInit={async () => {
    const connection = await openWebSocket();
    // Cleanup: close the connection on unmount
    return () => connection.close();
  }}
>
  <YourApplication />
</RgoInitializeProvider>
```
