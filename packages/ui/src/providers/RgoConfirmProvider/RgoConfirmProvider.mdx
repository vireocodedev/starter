# RgoConfirmProvider

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

Delivers an imperative confirmation dialog system via the `useRgoConfirm()` hook. Any component in the tree can trigger a fully styled MUI `Dialog` without managing open/close state locally.

---

## Why it exists

Confirmation dialogs are a cross-cutting concern. Without a centralized provider, every component that needs a "Are you sure?" dialog would need to:

1. Maintain its own `open` state.
2. Render its own `<Dialog>` JSX.
3. Handle loading states during async confirm actions.
4. Duplicate cancel/confirm button logic.

`RgoConfirmProvider` eliminates all of that. A single shared dialog lives at the provider level, and any descendant can invoke it imperatively.

---

## Provider setup

```tsx
import { RgoConfirmProvider } from "@vireocodedev/starter-ui";

function App() {
  return (
    <RgoConfirmProvider>
      <YourApplication />
    </RgoConfirmProvider>
  );
}
```

No props required.

---

## Consumer hook — `useRgoConfirm()`

The primary way to interact with this provider.

### Signature

```ts
function useRgoConfirm(): (dialogUiProps: RgoConfirmDialogUiProps) => void;
```

Returns a single function: call it with dialog configuration, and the dialog opens.

### Usage

```tsx
import { useRgoConfirm } from "@vireocodedev/starter-ui";

function DeleteUserButton({ userId }: { userId: string }) {
  const confirm = useRgoConfirm();

  const handleClick = () => {
    confirm({
      title: "Delete user",
      message: "This will permanently remove the user and all associated data.",
      color: "error",
      confirmText: "Delete",
      onConfirm: async () => {
        await api.deleteUser(userId);
        // Dialog closes automatically after onConfirm resolves
      },
    });
  };

  return <button onClick={handleClick}>Delete</button>;
}
```

### Error handling

If `useRgoConfirm()` is called outside of `RgoConfirmProvider`, it throws:

```
Error: useRgoConfirm must be used within a ConfirmProvider
```

## Behavior details

### Loading state

While `onConfirm()` is pending:

- The confirm button shows a `CircularProgress` spinner.
- Both buttons are disabled.
- The dialog cannot be closed (close button becomes a no-op).

This prevents double-submission and accidental dismissal during async operations.

### HTML message support

When `message` is a `string`, it is parsed as HTML via `html-react-parser`:

```tsx
confirm({
  title: "Deactivate account",
  message: "User <strong>john@example.com</strong> will be deactivated.<br/>This can be reversed later.",
  onConfirm: async () => {
    /* ... */
  },
});
```

When `message` is JSX (ReactNode), it renders as-is:

```tsx
confirm({
  title: "Transfer ownership",
  message: (
    <Stack spacing={1}>
      <Typography>Transfer all assets from:</Typography>
      <Chip label={currentOwner.name} />
      <Typography>To:</Typography>
      <Chip label={newOwner.name} color="primary" />
    </Stack>
  ),
  onConfirm: async () => {
    /* ... */
  },
});
```

### Auto-close on confirm

The dialog closes automatically when `onConfirm()` resolves. There is no need to manually control the open state. If `onConfirm` throws, the loading state ends but the dialog stays open so the user can retry or cancel.

## Context shape (advanced)

For rare cases where `useRgoConfirm()` is insufficient (e.g., class components), the raw context is exported:

```tsx
import { RgoConfirmContext, type RgoConfirmDialogUiProps } from "@vireocodedev/starter-ui";

// Context value type:
type ConfirmAction = (dialogUiProps: RgoConfirmDialogUiProps) => void;
```

## Common patterns

### Destructive action with error color

```tsx
confirm({
  title: "Delete all records",
  message: "This action is irreversible. 847 records will be permanently deleted.",
  color: "error",
  confirmText: "Delete all",
  onConfirm: async () => {
    await api.deleteAllRecords();
  },
});
```

### Confirmation with custom button labels

```tsx
confirm({
  title: "Submit for approval",
  message: "The document will be sent to the review team.",
  color: "primary",
  confirmText: "Submit",
  cancelText: "Not yet",
  onConfirm: async () => {
    await api.submitDocument(docId);
  },
});
```

### Wide dialog with rich content

```tsx
confirm({
  title: "Review changes",
  maxWidth: "md",
  message: <DiffViewer oldValue={previous} newValue={current} />,
  onConfirm: async () => {
    await api.applyChanges(changeSet);
  },
});
```

## Nesting order

Must be placed **after** `RgoThemeProvider` (uses MUI `Dialog`, `Button`) and **after** `RgoLocalizationProvider` (default button labels use `t()` for translation):

```
RgoThemeProvider
  └─ RgoLocalizationProvider
       └─ RgoConfirmProvider    ← here
            └─ ...
```

---

## Key details

- **One dialog at a time** — a single `<Dialog>` instance is rendered at the provider level. Calling `confirm()` again while a dialog is open replaces it.
- **Default labels are translated** — cancel/confirm buttons use `useTranslationLocal()` internally, mapping to `common.cancel` and `common.confirm` keys.
- **Uses `RgoDialogHeader`** — consistent dialog header styling with optional colored accent bar.
- **Context value is a function** — the context does not expose open/close state, only the trigger function.
