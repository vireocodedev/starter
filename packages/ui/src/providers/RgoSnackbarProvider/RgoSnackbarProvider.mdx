# RgoSnackbarProvider

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

Configures toast notifications powered by `react-hot-toast`. Renders a global `<Toaster>` with configurable position and duration. Consumers trigger toasts via the `toast()` function — no hook wrapper needed.

---

## Why it exists

Toast notifications (snackbars) are an app-wide concern. `react-hot-toast` needs a `<Toaster>` component mounted somewhere in the tree to display notifications. `RgoSnackbarProvider` standardizes that mount point and exposes sensible defaults while conforming to the `RgoProvider` type for composability.

---

## Provider setup

```tsx
import { RgoSnackbarProvider } from "@vireocodedev/starter-ui";

function App() {
  return (
    <RgoSnackbarProvider>
      <YourApplication />
    </RgoSnackbarProvider>
  );
}
```

With custom configuration:

```tsx
<RgoSnackbarProvider position="top-right" duration={3000}>
  <YourApplication />
</RgoSnackbarProvider>
```

## What it renders

```tsx
<>
  {children}
  <Toaster position={position} toastOptions={{ duration }} />
</>
```

The `<Toaster>` is rendered **after** children (not wrapping them). It uses a portal internally, so DOM position doesn't affect visual placement.

## Consumer API

### Basic toast with `react-hot-toast`

```tsx
import toast from "react-hot-toast";

function SaveButton() {
  const handleSave = async () => {
    await api.save(data);
    toast("Document saved");
  };

  return <button onClick={handleSave}>Save</button>;
}
```

### Styled toast with `RgoSnack`

The library ships an `RgoSnack` component designed to be rendered inside toasts for consistent visual styling:

```tsx
import toast from "react-hot-toast";
import { RgoSnack } from "@vireocodedev/starter-ui";

// Success notification
toast(<RgoSnack variant="success" message="User created successfully" />);

// Error notification
toast(<RgoSnack variant="error" message="Failed to save changes" />);

// Warning with custom adornment
toast(
  <RgoSnack
    variant="warning"
    message="Session expires in 5 minutes"
    endAdornment={<RefreshIcon />}
  />
);
```

## Advanced patterns

### Toast from outside React (services, interceptors)

`react-hot-toast`'s `toast()` is a standalone function — it works anywhere, not just inside React components:

```tsx
// In an API interceptor
import toast from "react-hot-toast";
import { RgoSnack } from "@vireocodedev/starter-ui";

api.interceptors.response.use(
  response => response,
  error => {
    if (error.response?.status === 401) {
      toast(<RgoSnack variant="error" message="Session expired. Please log in again." />);
    }
    return Promise.reject(error);
  }
);
```

### Promise-based toast

```tsx
import toast from "react-hot-toast";

function UploadButton() {
  const handleUpload = () => {
    toast.promise(api.uploadFile(file), {
      loading: "Uploading...",
      success: "File uploaded!",
      error: "Upload failed",
    });
  };

  return <button onClick={handleUpload}>Upload</button>;
}
```

### Dismissible toast

```tsx
import toast from "react-hot-toast";

const toastId = toast("Processing...", { duration: Infinity });
// Later:
toast.dismiss(toastId);
```

## Nesting order

Position is flexible. Typically placed after providers that might trigger toasts (e.g., after `RgoConfirmProvider`):

```
RgoThemeProvider
  └─ RgoLocalizationProvider
       └─ RgoConfirmProvider
            └─ RgoSnackbarProvider    ← here
                 └─ ...
```

## Key details

- **No custom React context** — `react-hot-toast` manages its own internal state.
- **No custom hook** — consumers import `toast` directly from `react-hot-toast`.
- **`RgoSnack` is optional** — you can pass plain strings to `toast()`, but `RgoSnack` provides consistent styling with variant-based coloring.
- **Single `<Toaster>` instance** — mounting multiple `RgoSnackbarProvider`s will render multiple `<Toaster>` components, which may cause duplicate toasts.
- **Type:** `RgoProvider<RgoSnackbarProviderProps>` — composable with `RgoProviders`.
