# RgoIconsProvider

![STABLE](https://img.shields.io/badge/STABLE-green?style=flat-square)

Type-safe, extensible icon registry system. Provides a centralized map of named icons as MUI `SvgIcon` components, delivered via React context. Consumer apps define their icon set through TypeScript declaration merging, achieving compile-time safety for icon names across the entire codebase.

---

## Why it exists

Large applications use dozens (or hundreds) of icons. Without a centralized registry:

- Icon imports scatter across hundreds of files.
- Typos in icon names are runtime errors, not compile-time errors.
- Swapping icon libraries (e.g., Lucide → Heroicons) requires touching every import.
- There's no single source of truth for "which icons does this app use?"

`RgoIconsProvider` solves all of this with a registry pattern: icons are declared once, typed globally, and consumed by name.

---

## Architecture overview

```
1. RgoIconRegistry (interface)     — augmented by consumer app
2. RgoIconsProvider (component)    — receives icon map, converts to MUI SvgIcons
3. RgoIconsContext (React context) — holds { muiIconsMap }
4. useRgoIcons() (hook)               — reads the context
5. RgoIcon (component)             — renders an icon by name
```

## Setup — 3 steps

### Step 1: Augment the type registry

In a `.d.ts` file in your consumer app:

```ts
// src/types/icons.d.ts
declare module "@vireocodedev/starter-ui" {
  interface RgoIconRegistry {
    "arrow-right": React.ComponentType;
    "arrow-left": React.ComponentType;
    user: React.ComponentType;
    settings: React.ComponentType;
    trash: React.ComponentType;
    download: React.ComponentType;
  }
}
```

This enables **compile-time validation** — using `<RgoIcon icon="typo" />` will be a TypeScript error.

### Step 2: Provide the icon components

```tsx
import { RgoIconsProvider } from "@vireocodedev/starter-ui";
import { ArrowRight, ArrowLeft, User, Settings, Trash, Download } from "./svg-icons";

const APP_ICONS = {
  "arrow-right": ArrowRight,
  "arrow-left": ArrowLeft,
  user: User,
  settings: Settings,
  trash: Trash,
  download: Download,
};

function App() {
  return (
    <RgoIconsProvider icons={APP_ICONS}>
      <YourApplication />
    </RgoIconsProvider>
  );
}
```

### Step 3: Use icons anywhere

```tsx
import { RgoIcon } from "@vireocodedev/starter-ui";

<RgoIcon icon="user" />
<RgoIcon icon="trash" color="error" />
<RgoIcon icon="download" width={32} height={32} />
```

## Consumer hook — `useRgoIcons()`

### Signature

```ts
function useRgoIcons(): {
  muiIconsMap: { [K in keyof RgoIconRegistry]: typeof SvgIcon };
};
```

### Usage

```tsx
import { useRgoIcons } from "@vireocodedev/starter-ui";

function NavigationMenu() {
  const { muiIconsMap } = useRgoIcons();

  const HomeIcon = muiIconsMap["home"];
  const SettingsIcon = muiIconsMap["settings"];

  return (
    <nav>
      <HomeIcon fontSize="small" />
      <span>Home</span>
      <SettingsIcon fontSize="small" />
      <span>Settings</span>
    </nav>
  );
}
```

### Error handling

Throws if called outside `RgoIconsProvider`:

```
Error: useIconComponent must be used within a RgoIconProvider
```

## How icons are converted

Raw SVG components are converted to MUI `SvgIcon` instances via `createSvgIcon()`:

```ts
// Internal — for each entry in the icons map:
createSvgIcon(<YourRawSvgComponent />, "icon-name");
```

This ensures:

- Icons inherit MUI theme colors (`color="primary"`, etc.).
- Icons respond to `fontSize` prop (`"small"`, `"medium"`, `"large"`, `"inherit"`).
- Icons work consistently with MUI components like `IconButton`, `ListItemIcon`, etc.

The conversion is **memoized** — `muiIconsMap` only recomputes when the `icons` prop reference changes.

## Type safety in action

```tsx
// ✅ Compiles — "user" is in the registry
<RgoIcon icon="user" />

// ❌ TypeScript error — "usr" is not in the registry
<RgoIcon icon="usr" />
//              ^^^ Type '"usr"' is not assignable to type 'RgoIconName'

// ❌ TypeScript error — missing icon in provider
<RgoIconsProvider icons={{ user: UserIcon }}>
//                        ^^^^^^^^^^^^^^^^
// Property 'settings' is missing in type '{ user: ... }'
```

## Nesting order

Should be placed **after** `RgoThemeProvider` (icons inherit theme colors) and **before** components that render `RgoIcon`:

```
RgoThemeProvider
  └─ RgoIconsProvider    ← here
       └─ RgoLocalizationProvider
            └─ RgoConfirmProvider
                 └─ ...
```

## Real-world consumer app pattern

```tsx
import { RgoIconsProvider, type RgoProvider } from "@vireocodedev/starter-ui";
import { APP_ICON_REGISTRY } from "./icons/registry";

export const AppIconsProvider: RgoProvider = ({ children }) => (
  <RgoIconsProvider icons={APP_ICON_REGISTRY}>{children}</RgoIconsProvider>
);
```

Where `registry.ts` maps all icon names to their SVG components:

```ts
// src/icons/registry.ts
import { ArrowRight } from "./ArrowRight";
import { User } from "./User";
// ...

export const APP_ICON_REGISTRY = {
  "arrow-right": ArrowRight,
  user: User,
  // ... all icons declared in the RgoIconRegistry augmentation
} as const;
```

## Key details

- **Custom React context** — `RgoIconsContext` is created and exported for advanced use.
- **Declaration merging** — the `RgoIconRegistry` interface is designed to be augmented; it extends `Record<RgoDefaultIconName, ComponentType>` as a base.
- **Memoized conversion** — icon map is only rebuilt when the `icons` prop reference changes.
- **Stroke-based convention** — `RgoIcon` defaults to `stroke="currentColor"` and `fill="none"`, suitable for outline icon sets (Lucide, Heroicons).
- **Type:** `RgoProvider<RgoIconsProviderProps>` — composable with `RgoProviders`.
