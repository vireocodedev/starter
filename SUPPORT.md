# Support

Vireo is a public `0.x` open-source project maintained on a best-effort basis.
There is no guaranteed response or resolution time for public support requests.

## Where to ask

- Use the repository's structured bug form for reproducible defects.
- Use the feature-request form for a bounded proposal and its use case.
- Use a pull request for a reviewed code or documentation change after reading
  [CONTRIBUTING.md](CONTRIBUTING.md).
- Follow [SECURITY.md](SECURITY.md) for suspected vulnerabilities. Never put
  vulnerability details in a public issue.

Before opening an issue, search existing issues and confirm the behavior against a
supported release and environment. Include the affected package or Maven artifact,
exact version, minimal reproduction, expected behavior, actual behavior, and relevant
environment details. A repository checkout is not required when a published-package
reproduction is possible.

## Support boundary

Maintainers may prioritize security, correctness, release integrity, and broadly
reusable framework work over individual application questions. The project does not
provide private consulting, production operations, application-specific architecture
approval, or emergency support. Application teams remain responsible for domain
rules, authorization, sensitive data, deployment, offline eligibility, and conflict
resolution.

Issues may be closed when they cannot be reproduced, concern unsupported versions or
private APIs, lack requested information, or fall outside the framework boundary.
Constructive reports may remain open without implying a delivery commitment.

## Conduct and privacy

Participation is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Use test data
and remove credentials, personal data, and confidential application details from all
public reports.
